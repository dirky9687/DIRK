# Responsible testing & security issues

DIRK is intended for learning and **authorized** network security testing. Do not use it to target third-party devices or networks without permission.

Before opening a public issue, remove real SSIDs, BSSIDs, GPS positions/routes, passwords, API keys, BLE device addresses, private packet captures and identifying traces. Share sensitive vulnerability findings privately with maintainers rather than posting exploitation instructions or private data in public issues.

Security caveats: passive 5 GHz results via MonsterC5 may lack security detail; PMF and WPS learning labs include offline or hypothetical analyses; transmitted packet status is not evidence of client impact. Review regional radio restrictions and local law.
